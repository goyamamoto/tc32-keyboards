# CIDOO V21 (`cidoo_v21`)

ZMK on the CIDOO V21, a 21-key numpad with a knob on the Telink TLSR8278. It is built on the same template as the [V75 Pro](../cidoo_v75pro/README.md) (the same USB IDs, flash layout and update protocol); the pins, the layout, the backlight and the keymap differ. The firmware installs over the USB cable with the update protocol of the keyboard's original firmware, which stays in the other flash slot as the way back. The image to install is the full build ([Build](#build)): wired, Bluetooth and 2.4G through the mode switch, the backlight, ZMK Studio.

| Part | Setting |
|---|---|
| Matrix | `cidoo,led-key-matrix`: the matrix columns also drive the backlight's LED columns, so one driver scans the keys and lights the LEDs; a full key scan about every 6.5 ms |
| Columns | PB4 PB5 PB7 PC0 PA7 PA1 PA0 PD5 PD4 PD3 PD2 PC5 (active high; PA7 is the SWS pin, so there is no SWS while this firmware runs) |
| Rows | PC2 PC1 (active high, pull-down) |
| Knob | `cidoo,detent-encoder` on PD0 and PC3: volume up and down; the press is mute |
| Backlight | 21 RGB LEDs: the wave, breathe and light effects, preset colours and a colour wheel, 10 brightness levels, 5 speeds, white mixed in. The setting is kept over a power cut. Keys, on the Fn layer: Backspace on/off, Enter the next effect, * and / the colours and multicolour, 5 and 6 less and more white, + and - the brightness, 8 and 7 faster and slower; only on/off acts while the backlight is off |
| Num Lock LED | The host's Num Lock (over USB, Bluetooth or the 2.4G dongle) lights the Num key white over the effect, at every brightness level. Nothing is lit while the backlight is off or dark. macOS sends no Num Lock |
| Mode switch | Three positions: the middle is wired (USB; with the cable out the power is off), the end nearer the USB socket Bluetooth, the other end 2.4G. A move while running restarts the keyboard in the new position. Before the confirm that restart counts as a boot: move the switch after the confirm |
| Battery | PB3; PD7 is power in, PD6 charging |
| USB suspend | The backlight goes dark 1 s after the host suspends the bus; a key wakes the host |
| Sleep | Bluetooth: deep sleep after 20 s of advertising to a bonded host (60 s while it waits for a pairing) with no connection, or at 0 % on battery; a low-power state after 5 minutes connected without a key. 2.4G: a low-power state after 5 minutes without a key, deep sleep after 30 minutes or on the dongle's sleep command. Not while a USB host has the keyboard over the cable. A key, the mode switch or the cable wakes it |
| Flash | The V75 Pro's layout. This firmware keeps its own data apart from the original firmware's, so going back keeps the original firmware's settings |
| Updates | Over a second USB HID interface ([Firmware updates over USB](https://github.com/goyamamoto/zmk-tc32/blob/main/tc32/README.md#firmware-updates-over-usb)) |
| Going back | While the firmware runs: Fn + KP0 held 15 s, then released (`&prev_fw`); the hold is long so that a finger slipping onto KP0 during a pairing does not leave the firmware. In the BT or 2.4G position with no host connected the keyboard sleeps 20 s (60 s while it waits for a pairing) after it starts advertising, and a hold not ended by then does nothing; the power-on chord is the way back then. At power-on: Fn + KP- held ([The two slots and the way back](https://github.com/goyamamoto/zmk-tc32/blob/main/tc32/README.md#the-two-slots-and-the-way-back)) |
| Studio | ZMK Studio over a USB serial port, in any position of the switch while the cable is in; a keymap changed over USB is the keymap in all three. Fn + KP. (the numpad's Del) unlocks it; it locks again after 10 minutes without a request. Keep `&studio_unlock` and `&prev_fw` bound when rebinding keys |
| Wireless keys | Fn + KP1, KP2, KP3: Bluetooth profiles 1-3 (a tap selects the profile, held 3 s it also clears its bond; only in the BT position; a host lists them as `V21 ZMK 1`, `2` and `3`). Fn + KP4 held 3 s in the 2.4G position: pair with the CIDOO dongle again |
| Pairing | Secure Connections with Passkey Entry: the host shows a passkey, type its digits on the keypad, then KP Enter (Backspace takes a digit back, Escape gives the pairing up). A host that offers only legacy pairing is refused |

## Keymap files

- `cidoo_v21-layouts.dtsi` and `cidoo_v21.keymap` are generated by `gen_v21.py` from the keyboard's VIA definition and default keymap (the inputs are not in this repository).
- `cidoo_v21_ble.keymap` adds the wireless keys; `cidoo_v21_studio.keymap` adds Studio's unlock key: the image for a keyboard.

## Build

In a workspace set up as [README.md](../../../README.md#build) describes, from `tc32-keyboards/`:

```sh
./build.sh cidoo_v21
```

This is the full build, the image to install, in `<workspace>/build/cidoo_v21-studio/zephyr/zmk.ota.bin`. `./build.sh cidoo_v21 ble` gives the wireless build without Studio, `./build.sh cidoo_v21 wired` the wired build.

## Install

**At your own risk.** This firmware replaces the keyboard maker's firmware. Installing it, using it or going back from it can make the keyboard unusable, lose its settings and pairings, or end the maker's warranty. It comes with no warranty of any kind (see the [licence](../../../README.md#licence)) and with no support: nobody, neither the authors nor CIDOO, Telink, the ZMK or the Zephyr projects, can help you or takes any responsibility for what happens to your keyboard, your computer or your data. The way back to the original firmware described here worked on the keyboards it was tried on; that is not a promise that it will work on yours. If you are not prepared to lose the keyboard, do not install this.

Follow [INSTALL.md](../../../INSTALL.md) step by step; it names this board's strings and keys. In short, with the keyboard plugged in, the mode switch in the wired position:

```sh
python3 ../zmk/tc32/scripts/telink_ota.py check   zmk.ota.bin
python3 ../zmk/tc32/scripts/telink_ota.py flash   zmk.ota.bin --vid 320f --pid 5055 --product "CIDOO V21" --yes
python3 ../zmk/tc32/scripts/telink_ota.py info    --vid 1d50 --pid 615e --product "V21 ZMK"
python3 ../zmk/tc32/scripts/telink_ota.py confirm --vid 1d50 --pid 615e --product "V21 ZMK"
```

Confirm within three boots, after the go-back key (Fn + KP0 held 15 s, then released) and the power-on chord have each taken the keyboard back to the original firmware once and the firmware was installed again. Charge the keyboard before the first install.
